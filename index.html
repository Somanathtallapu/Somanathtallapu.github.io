CASE-001

Home SOC lab: brute force detected, scan missed

DetectionClosed

Kali attacks, Wazuh watches. The SMB brute force was caught and mapped to MITRE T1110. The Nmap scan was invisible, which exposed a real coverage gap.

Hide case details ▲Open case details ▼
  1. SetupVirtualBox host-only network (192.168.56.0/24): Kali attacker, Metasploitable2 target, Wazuh 4.14.5 OVA (manager, indexer, dashboard), and my Windows 11 laptop as the monitored endpoint.
  2. Attack 1Ran nmap -sV against Metasploitable2. Wazuh showed nothing, because the target had no agent. The SIEM can only see where it has eyes.
  3. Attack 2Brute-forced SMB on the Windows endpoint with NetExec. Every failed login produced a Windows 4625 event.
  4. DetectRule 60122 (logon failure, level 5) fired per attempt, then rule 60204 (multiple failures, level 10) fired on the pattern. That escalation is what an analyst acts on.
  5. FixAgent installed but never connected: ossec.conf pointed at 0.0.0.0 instead of the manager IP. Install silently failed until run as administrator. Hydra could not talk to Windows 11 SMB, so I switched to NetExec and opened port 445 to the lab only, then removed the rule.
Alert
rule.id:    60204  (level 10)
rule.desc:  Multiple Windows logon failures
event:      4625 (failed logon)
agent:      somu (Windows 11)
src:        kali 192.168.56.101
mitre:      T1110 Brute Force
Tools
Wazuh 4.14.5Kali LinuxNmapNetExecHydraMetasploitable2Windows 11VirtualBox
Lesson

"Installed" and "working" are not the same thing, and no alert does not mean no attack.

CASE-002

Active Directory identity lab on Windows Server 2025

IdentityClosed

Built the somu.local domain from scratch: joiner/mover/leaver, RBAC, delegated admin, Group Policy, password policy, gMSA and audit logging. Found and fixed 6 weak defaults.

Hide case details ▲Open case details ▼
  1. DomainPromoted DC01 with a static IP, AD DS and DNS; verified the A records; built Finance, HR and IT OUs and users with department and title metadata.
  2. JMLAccess only through role groups. Movers lose old access to stop privilege creep. Leavers are disabled, not deleted, and stripped of groups.
  3. RBACAGDLP group design, nested groups, and Get-ADGroupMember -Recursive to answer "who actually has this access?"
  4. DelegateHelpdesk can reset passwords in the HR OU only. Verified the ACEs, and confirmed no rights on Finance.
  5. PolicyScreen-lock GPO and precedence testing; a 20-character, lockout-after-3 PSO for Domain Admins; SPN service account vs gMSA.
  6. AuditEnabled auditpol subcategories and tracked 4624/4625, 4720, 4728, 4740, 4769 and 5136, pivoting on Logon ID.
Key finding

A new PSO defaulted to reversible password encryption, a setting I never chose. Caught it by reading back every property, then fixed it.
