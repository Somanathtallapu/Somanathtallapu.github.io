CASE-001

SMB brute-force attack detected in a home SOC lab

DetectionClosed

Built a Wazuh SIEM lab, attacked a Windows 11 host from Kali Linux, and confirmed the alerts mapped to MITRE ATT&CK T1110.

Hide case details ▲Open case details ▼
  1. SetupBuilt a virtual lab in VirtualBox on an isolated host-only network (192.168.56.0/24) so attack traffic stays off the home network.
  2. DeployInstalled Wazuh 4.14 on an Ubuntu VM as the SIEM and enrolled Windows 11 as a monitored endpoint with the Wazuh agent.
  3. AttackFrom Kali Linux, ran an SMB brute-force attack against Windows 11 with NetExec to generate real failed-logon events. Metasploitable2 served as an extra target.
  4. DetectWazuh fired rule 60122 (logon failure) and rule 60204 (multiple failed logons). Reviewed the Windows Security events behind each alert and mapped the activity to T1110 Brute Force.
  5. FixLogs were not reaching the SIEM at first. Traced it through Windows Firewall rules, PowerShell elevation, an ossec.conf misconfiguration on the agent, and SMBv1 compatibility for NetExec.
  6. ReportPublished a GitHub README with an architecture diagram, attack steps, alert screenshots and lessons learned.
Sample alert
rule.id:    60204
rule.desc:  Multiple Windows logon failures
agent:      windows11
src.host:   kali (192.168.56.0/24)
mitre:      T1110 Brute Force
status:     confirmed true positive
Tools
Wazuh 4.14UbuntuKali LinuxNetExecWindows 11Metasploitable2VirtualBoxPowerShell
Lessons learned

A detection is only as good as its log pipeline. Most of the work was making sure events actually reached the SIEM.

CASE-002

User lifecycle in Microsoft Entra ID: joiner, mover, leaver

IdentityClosed

Handled the full account lifecycle the way an IAM or help desk team does through access requests and offboarding tickets.

Hide case details ▲Open case details ▼
  1. JoinerCreated new user accounts in Microsoft Entra ID and added them to the security groups that matched their role.
  2. MoverHandled a role change by removing access the user no longer needed and adding access for the new role.
  3. LeaverDisabled departing users' accounts to block sign-in and removed their group-based access.
  4. ModelManaged permissions through security groups instead of one-by-one assignments, so access follows the role and is easy to review.
Tools
Microsoft Entra IDSecurity groups
Lessons learned

Group-based access keeps least privilege practical: when someone changes roles, you change their groups, not dozens of permissions.
